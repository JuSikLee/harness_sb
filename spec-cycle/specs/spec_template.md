# 글쓰기 첨삭 에이전트 — Spec

## 1. outcomes — 원하는 결과
(이 작업이 끝났을 때 무엇이 만들어져야 하는가)

결과물: outputs/review_{date}.docx 한 파일.
이 .docx는 다음 4개 섹션 구조를 가진다.
1. 헤더 + 면책: "# 글쓰기 첨삭 --- {원본 파일명} --- {날짜}" + "이 첨삭은 최종 결정이 아니며, 작성자의 의도가 우선합니다."
2. "전반 진단" 섹션: 4항목(문법 · 논리 · 톤 · 근거) 각각에 ★/△/√ 표시 + 한 줄 코멘트(원문 인용 포함).
3. "구간별 수정안" 섹션: 수정이 필요한 구간 3~5개. 각 항목은 "원문 인용 → 대안 1~2개 → 한 줄 이유" 형식.
4. "종합" 섹션: 한 단락(150자 이내). 감정 1줄 + 핵심 개선 포인트 1줄.

함께 생성되는 파일: runs/run_{date}.json --- Spec verification criteria로 채점한 결과 (pass/fail + 코멘트)
