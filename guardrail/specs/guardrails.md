# 이메일 답장 에이전트 - 가드레일

## 1. 항상 허용 (Always Allow)
다음 행동은 사용자 승인 없이 자동으로 실행됩니다.

- tests/emails/ 폴더의 메일 파일 읽기
- 답장 초안 생성 (LLM 호출)
- 답장 초안을 콘솔(터미널)에 출력
- 답장 초안을 agents/email-assistant/drafts/ 폴더 안의 파일로 저장
- 토큰 사용량 통계를 콘솔에 출력

공통 원칙: 외부에 영향을 주지 않는 행동만 자동 승인합니다. 외부 발송 · 공유는 어떤 경우에도 자동 승인되지 않습니다.

## 2. 항상 거부 (Always Deny)
다음 행동은 어떤 경우에도 실행되지 않습니다. 시도되면 즉시 중단하고 사용자에게 알립니다.

### 발송 관련
- 사용자 승인 없는 자동 메일 발송 (어떤 경우에도)
- 받은 메일의 발신자가 아닌 다른 주소로의 발송
- 본문에 비공개 정보가 검출된 답장의 발송 (4번 섹션 패턴)
- 동시에 5명 이상의 외부 수신자에게 발송

### 정보 노출
- 받은 메일의 발신자 정보를 외부 시스템에 기록
- 메일 본문을 공개 클라우드 스토리지로 업로드
- 답장 초안을 회사 외부 시스템에 저장

### 권한 위반
- 회사 메일 시스템(SMTP · API)에 대한 임의 자격 증명 사용
- 사용자가 명시적으로 지정하지 않은 외부 도구 호출

원칙: "어떤 경우에도"가 핵심입니다. 사용자가 "괜찮으니 보내라"고 해도 항상 거부 목록에 있는 행동은 실행되지 않습니다. 정말 필요하다면 스펙을 바꾸고 재실행해야 합니다.

## 3. 사용자 승인 (User Approval)
다음 행동은 실행 전에 사용자 승인을 거칩니다.

### 항상 승인 필요
- 실제 메일 발송 (1명에게 보내든 여럿에게 보내든)
- 답장 본문에 일정 · 약속이 들어간 경우 ("만나 뵙겠습니다", "X일에 회신드리겠습니다" 등)
- 답장에 첨부 파일이 포함된 경우
- 답장이 외부 도메인으로 가는 경우 (자기 회사 도메인 외)

### 승인 요청 화면 형식

```
[사용자 승인 필요]
행동: 메일 발송
받는 사람: contact@partner-company.com
제목: Re: 협력 제안
약속/일정: "다음 주 화요일 오후 3시 미팅 가능합니다"
첨부: (없음)

계속하시겠습니까? (y/n):
```

### 승인 결과 처리
- y: 발송 진행
- n: 발송 취소, 초안은 그대로 유지
- 입력 시간 30초 초과: 자동으로 n 처리 (사용자 부재 시 안전)

## 4. 비공개 정보 검출 (Sensitive Info Detection)
답장 초안을 발송하기 전에 다음 패턴을 자동 검출합니다.

### 정규식 기반 (결정론적)
- 주민번호 패턴: `\d{6}-\d{7}`
- 신용카드 번호: `\d{4}-\d{4}-\d{4}-\d{4}`
- 휴대폰 번호 (자기 회사 임직원이 아닌 사람)
- 사내 IP 주소 패턴

### 키워드 기반
- 연봉, 급여, 상여, 보너스, 인센티브
- 인사 평가, 고과, 성과급, 직급 조정
- M&A, 인수, 합병, 매각
- 미공개 프로젝트 코드네임 (별도 키워드 사전 파일에서 정의)
- 사내 시스템 이름 (외부에 노출되면 안 되는 이름들)

### 검출 시 처리

발송 직전에 검출되면:
- 항상 거부 카테고리로 분류
- 검출 항목과 위치를 화면에 표시
- 사용자가 발송 시도해도 차단
- 사용자에게 "초안에서 비공개 정보를 제거한 뒤 다시 시도하세요" 안내

초안 생성 단계에서 검출되면:
- 사용자에게 경고 표시
- 초안은 그대로 두되 발송 시 추가 확인 필수
- 콘솔에 "이 초안에는 비공개 정보가 포함되어 있습니다 - 확인 후 발송하세요" 메시지

### 받은 메일에 비공개 정보가 있을 때
- 모델에게 "받은 메일의 비공개 부분을 답장에 인용하지 마라"고 시스템 프롬프트에 명시
- 그래도 모델이 인용하면 검출되어 차단됨

## 5. 입력 마스킹 (Input Redaction - Hook)
1. LLM 호출 직전에 받은 메일 본문에 4번 섹션의 정규식 패턴을 적용하고, 매칭된 문자열을 `[REDACTED_TYPE_N]` 형식의 자리표로 치환한다. 원본 매칭값과 자리표의 매핑 표는 메모리에만 둔다 (파일 저장 금지).
2. LLM 응답을 받은 뒤, 자리표가 답장에 남아 있으면 자동 폐기하고 사용자에게 "마스킹된 정보가 답장에 인용됨 - 폐기됨"을 알린다.
3. 자리표가 남아 있지 않으면 그대로 발송 단계로 넘긴다.
4. 매핑 표는 한 번의 메일 처리가 끝나면 즉시 메모리에서 삭제한다.
